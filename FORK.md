# Stump fork (`fork/main`)

A small fork of [Stump](https://github.com/stumpapp/stump) for a large, mostly-EPUB
library that is browsed from the web and from KOReader. It is based on the upstream
`metadata-based-libraries` branch (nightly + metadata organization) and keeps every
change small and upstreamable.

## What the fork adds

| Area | Feature |
|---|---|
| Libraries | *(upstream branch)* **Metadata organization**: series come from book metadata (EPUB `calibre:series` / EPUB 3 collections / ComicInfo), books without a series stay standalone, folders are ignored |
| OPDS 1.2 | **Shelves**: smart lists as navigation + book feeds |
| OPDS 1.2 | **Scoped search**: every book, library, series and shelf feed has its own `rel="search"` template, so KOReader's *Search* searches inside the feed being viewed |
| OPDS 1.2 | **Facets**: sort (best match while searching, title, rating, author, series order, recently added), language, minimum rating and age (general / adult), with `thr:count`; entries show `★ 4.1 · 18+` |
| OPDS 1.2 | **Authors / Genres** indexes: letter → value (with counts, searchable) → books; exact `?author=` / `?genre=` book filters |
| Web | **Authors** and **Genres** browse pages (`/browse/authors`, `/browse/genres`) with counts, letter jump bar and `Prefix:` grouping (e.g. `Estante: …` shelves) |
| Web | **Grid view for smart lists** (table/grid toggle + size slider), including series/library-grouped lists (one section per group) |
| Web | **One grid/table layout for every list**: the grid/table toggle switches libraries, series, search (incl. author/genre lists), smart lists and files together; saved per user on the server and shown in *Settings → Preferences → Book and series lists* |
| Web | **Tables use the full width**: single-line rows (ellipsis, full value on hover), small covers, names/people/series/genres share the free width while numbers and dates stay compact, and on phones the table scrolls sideways instead of growing tall rows; new *Series* column (name and number). *Adjust columns* scrolls and keeps Cancel/Save in view on phones, has drag handles, lists the series table's columns, and opens on the columns actually shown. Fixes the library series table crash and smart list rows that kept the previous columns' cells |
| Web | **Smart list grouping dialog** (*Group: …* button, live preview): ungrouped, series, library, or any book detail (author, genre/tag, language, publisher, year, decade, rating, age rating) or a `Key: *` pattern over genres and tags (e.g. `Asignatura: *`); `Key: value` schemes found in the list are one-click options. | Web | **Filters on smart lists**: the same filter drawer as library/series books (genre, writer, language, tags, read status, ...), offering only the values present in the list |
| Web / GraphQL | **Exact list matching** (`hasAnyOf` / `hasNoneOf`): `Estante: Ciencia` no longer matches `Estante: Ciencia ficción`; genre/author badges and the filter drawer use it |
| Metadata | **Ratings** (0-5): read from EPUB `calibre:rating` (0-10, halved), ComicInfo `CommunityRating`, or Stump's precise `bcurator:rating` (an EPUB `<meta>` or a PDF keyword field, see below); editable through `rating` in `MediaMetadataInput` (written back into the file, locked as `RATING`); new `rating` column (needs a *Rebuild metadata* scan to fill) |
| Metadata | **PDF series, age and rating**: PDFs have no such fields, so Stump keeps them in the PDF Keywords as its own keyword fields: `bcurator:series=`, `bcurator:series_index=`, `bcurator:age=` (`18+` / `All ages`) and `bcurator:rating=` entries (the prefix the library's files already carry) are read like the EPUB fields, and written by *Add books* and metadata edits; the other keywords are the PDF's **genres** (like EPUB `dc:subject`), so PDFs appear in the Genres pages, genre filters and genre smart-list rules; PDFs then join metadata series |
| Web | Filter drawer gains **language**, **tags**, **minimum rating** and **age** (general / adult); sort by rating or age rating; rating columns in tables; `rating` in smart list rules |
| Web | Book cards show **★ rating** and an **18+** badge; in a series they show the book's **#number** on the cover; the book page shows rating and age |
| Web | Book pages show the **whole series** (*Books in this series*, linking to the series): every book in series order, the current one outlined and scrolled into view; upstream's *Next in series* only listed the books after it. A **More by <author>** row follows (standalone books have no series row) |
| Web / OPDS | **Search**: split into words, every word must start a word of the book's file name, title, series, writers, publisher, genres or tags (any order, case- and accent-insensitive: `brown chemistry`, `quim`, `fisica diploma`); series match on name/title. Same rules in the web lists, the home box, smart lists (in the browser) and OPDS 1.2/2 |
| Web | **Back returns to the search**: searches live in the URL (`?search=`, home `?q=`, Authors/Genres `?q=`), typing doesn't add history entries; grouped smart lists open the matching groups and show only the matching books |
| Web | **Back returns to where you were**: back/forward (and reloads) put every page at the scroll position it was left at (lists, grids, tables, grouped smart lists with the same groups open, Authors/Genres, Home and its rows, book pages), waiting for the page's data and stopping as soon as you scroll; new pages start at the top. Kept per history entry in the tab's session storage. Virtualised lists stay bound to the main scroller, so a fast fling back to the top after going back no longer shows an empty top |
| Web | **Same search toolbar on every list**: Home, Explore, Authors and Genres are laid out like a library's books (the page title, then a toolbar with the search first and the page's sort, filter and layout controls at the end); the home search keeps its quick results, and smart lists put their search first too |
| Web | **Compact list toolbar**: grid/table is one toggle (it shows the layout it switches to); every list toolbar has the same order on desktop and phones (search, save, filter, group, layout, ⋯), and on phones it's one row: the search is an icon (a dot while a search is active) that opens across the row while the other controls step aside; smart lists show *Group* (a dot while grouped) and *Save* as icons, with the saved views and *Adjust columns* under ⋯; on wider screens the search is a compact input that widens in use; a header's lone tab (a smart list's *Items*, a book's *Overview*) is hidden |

| Web | **One reader frame for EPUB, PDF and comics**: the pages take the whole screen; a slim top bar (back, contents or pages, search, bookmark, and the reading settings as a monoline `Aa` glyph, shown pressed while open) lies over them, shows when the book opens, when the mouse nears the top or on a tap in the middle (phones), and slides away. The reading settings are an **"ink and paper" `Aa` panel** over the page, without dimming it: printed with the book's own ink on its own paper (options in ink at 80% on a track of ink at 7%, the chosen one inked solid; orange only for keyboard focus and switches), a 320px card under the button on wider screens, a bottom sheet with a drag handle on phones. In order: paper samples (Auto split light/dark) and full screen; the reader's own rows; the pages (four small drawings: one or two pages, turned or scrolled; two pages need a wide screen, flowing EPUB text scrolls in one column, comic spreads turn page by page); a footer with *More* (direction, cover alone, the comic's crop and wide pages, the reading progress) and *Shortcuts* (also on `?`). An EPUB's *Return* chip after a link is the same step. Choosing the chapter being read in an EPUB's contents goes back to its start (it did nothing when the entry was a whole page, as in ePubLibre books). `F11` takes the reader to the page's own full screen (all the browser's bars hidden, Firefox's tab bar included). `Ctrl/Cmd+F` or `/` open the reader's search (not the browser's find bar or Firefox's quick find); `/` also opens the list search on every list page. **Keys that move the way the layout reads**, the same in the three readers: in the scrolled layouts (EPUB scroll, PDF continuous, the comic strip) `↑`/`↓` scroll a line, `Space`/`Shift+Space` and `PgDn`/`PgUp` a screen and `Home`/`End` go to the start/end (an EPUB scrolls its chapter whether the focus is on the page or in the book, goes on to the next chapter from its end, and no longer jumps chapters on `←`/`→`); pages that turn also turn with `Space`, `PgUp` and `PgDn` (EPUB). A zoomed PDF page is moved around by the arrows and `Space`, which stop at its edges, and a tap at its side doesn't turn it: only `PgUp`/`PgDn` turn pages (a comic page bigger than the screen is stepped through and turns after its last part, see below). The key moves take 110ms, easing out; a press during a move retargets it, so a held key moves on steadily; reduced motion jumps. The shortcuts sheet lists the keys of the layout on screen. The bars, the page number, the EPUB text and the PDF pages keep clear of camera cutouts (safe-area insets, also in landscape), and the readers show no scrollbar at the edge. **One set of gestures in every reader** (`shared/gestures`): in the layouts where pages turn, a tap on a third of the width at each side of a touch screen (a quarter with a mouse; EPUB text keeps mouse clicks for selecting, with chevrons in the margins) turns the page, mirrored for right-to-left books, and the middle shows or hides the controls; in the scrolled layouts a tap never turns anything (an EPUB's side taps jumped to the next chapter there). A page at its fit stays put under a finger; a deliberate sideways swipe, judged when the finger lifts (past 16px, mostly sideways, within 900ms, a flick or a quarter of the screen), turns it without dragging it along |

## Metadata automation API

For scripts that fix metadata in bulk. Everything goes through GraphQL at `/api/graphql`; an API key
(*Settings → API keys*, for a user with *Access API keys*) works as a Bearer token. The key needs
*Edit metadata* (an *Inherit* key gets the user's permissions; a custom key must list
`EDIT_METADATA`).

- `mediaByPaths(paths: [String!]!)`: the books at these paths (as Stump stores them, e.g.
  `/biblioteca/biblioteca/Umberto_Eco/El_nombre_de_la_rosa.epub`), in order, `media: null` when
  there is none (`mediaByPath` does one).
- `editMediaMetadataBatch(inputs: [MediaMetadataBatchInput!]!, options: MediaMetadataBatchOptions)`:
  each input names a book by `id` or `path` and carries a `MediaMetadataInput` (the editor's
  fields: `title`, `writers`, `series`, `number`, `genres`, `summary`, `publisher`, `year`,
  `language`, `ageRating`, `rating` 0-5, identifiers, ...; omitted fields stay, `null` clears).
  Options: `dryRun` (default `false`: report what would change, save nothing) and `writeToFile`
  (default `true`; `false` keeps the changes in Stump only). Up to 500 items per call. Each item is
  saved like the *Edit details* dialog does (written into the file and read back before it
  replaces the book, database, locked fields, edit history), one book at a time, and one failing
  item doesn't stop the others. The result lists every item in order: `status` (`SAVED`,
  `UNCHANGED`, `WOULD_SAVE`, `FAILED`, `NOT_FOUND`), the `changes` (field, old and new value,
  whether the file has it), `file` (`WRITTEN`, `NOT_NEEDED`, `SKIPPED`, `FAILED` and why),
  `saveId` (undo it with `revertMediaMetadataEdit(mediaId, saveId)`) and `errors`; then
  `rescanBooks`: the books whose files changed are read again by one `book_rescan` job (no library
  scan per book: Stump's own writes never set the library watcher off).

```bash
curl -s https://stump.example/api/graphql \
  -H "Authorization: Bearer $STUMP_API_KEY" -H 'Content-Type: application/json' \
  -d @- <<'JSON'
{"query": "mutation($inputs: [MediaMetadataBatchInput!]!, $options: MediaMetadataBatchOptions) { editMediaMetadataBatch(inputs: $inputs, options: $options) { saved failed notFound rescanBooks items { index path status saveId errors changes { field oldValue newValue writtenToFile } file { status message } } } }",
 "variables": {
   "options": {"dryRun": true},
   "inputs": [
     {"path": "/biblioteca/biblioteca/Umberto_Eco/El_nombre_de_la_rosa.epub",
      "input": {"genres": ["Historical Fiction", "Mystery & Thriller"], "rating": 4.1}},
     {"id": "96583e0a-2dde-45bb-8b3d-63f3789df9a1", "input": {"series": "Cambridge Concise Histories", "number": 3}}
   ]}}
JSON
```

Run it with `"dryRun": true` first, then without. Online lookups (*Add books*, *Suggest genres*)
use an optional Google Books API key set in *Settings → Metadata → Online lookups*
(`updateOnlineLookupSettings(googleBooksApiKey:)`, server managers; stored encrypted, never sent
back: `onlineLookupSettings { googleBooksApiKeySet }`).

## Switching an existing library to metadata organization

Upstream only lets you choose the organization when a library is created. An existing
filesystem library can be switched in place (keeps book IDs, tags, progress, smart lists):

1. Back up `stump.db`, stop the server.
2. `UPDATE library_configs SET organization_mode = 'METADATA' WHERE library_id = '<id>';`
3. Start the server and run a custom library scan with **Rebuild metadata**
   (`scanLibrary(id, options: {config: {regenMeta: true}})`).
4. Run **Clean library** to remove the now-empty folder series.

## Building

The helper scripts in `scripts/fork/` run in containers on a build host:

- `check.sh` — `cargo check` of the server
- `test.sh '<cargo test args>'` — unit tests
- `schema.sh` — regenerate `crates/graphql/schema.graphql`, then
  `node.sh 'cd packages/graphql && yarn codegen'` for the TS client
- `build-image.sh <tag>` — the upstream multi-stage `docker/Dockerfile`
- `map_stack.py <assets dir>` — map a stack copied from the web error screen to source
  (`docker cp stump-fork:/app/client/assets /tmp/stump-assets` first; builds ship hidden source maps)
- `build-local.sh <tag>` — faster: builds the server and web client with cached
  crates/node_modules and assembles `docker/Dockerfile.fork`
- `docker/Dockerfile.pdf-worker` — the PDF worker image for post-processing; built by the
  `stump-pdf-worker` service of `docker/compose.fork-postproc.example.yml`
  (`docker compose up -d --build`), see `scripts/fork/workers/README.md`
